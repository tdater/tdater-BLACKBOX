How it works THE LOOP

A project is the thing you're fixing: an app, a car, a garage door opener. Each problem in it is an investigation, and every investigation runs the same loop.

CaptureLogs, screenshots, photos, voice notes and measurements, filed under the problem.
PlanWrite the test and the expected result before you run it.
RunRecord the build, the environment, what you changed and the outcome.
CompareSee what changed between a pass and a fail, including what nobody wrote down.
ResumeA one-screen briefing of where you are and what to do next.
Hand offA clean fix request for another person or an AI chat, reviewed before it leaves.

Capture everything EVIDENCE

Evidence is copied into BLACKBOX's own storage, so it survives you deleting the original screenshot or clearing Downloads.

Text and logs

Paste a logcat dump, an error message or notes. Huge pastes are kept whole as an attached file instead of choking the app.

Files and photos

Import any file, or take a photo with the system camera. Share from any app straight into a project.

Voice notes

Record while your hands are busy under a dashboard. Recording survives folding and rotating the phone.

Measurements

Numbers with their units. Compare flags readings in different units as not comparable instead of lining up volts against amps.

App event logs

Your own apps can write a simple JSON event log. Import it and errors, warnings and marked events land on the timeline.

Withdraw, don't delete

Removing evidence deletes the file but keeps the record, and any claim that relied on it gets flagged.

Test runs that keep their story PLANS · OUTCOMES

Plans with revisions

  • Steps, the expected result and what to hold constant, written down first.
  • Editing a plan creates a new revision. Every run keeps a frozen copy of the exact revision it used.
  • A fixed failure can join the regression checklist, so it gets re-checked after the next change.

Every run records

  • The build, plus an environment snapshot: device, OS, connection, settings.
  • What you meant to change and what actually changed.
  • Outcome: ✓ PASS ✗ FAIL ◐ PARTIAL ? INCONCLUSIVE, or abandoned.
  • Measurements, timestamped markers and deviations from the plan.

Compare runs honestly UNKNOWN IS A VALUE

Most debugging mistakes come from assuming something didn't change because nobody wrote it down. BLACKBOX never treats a gap as "same".

Claims that know what they are CLASSIFIED

Every conclusion is labelled for what it is and cites the evidence and runs behind it. Accepting a claim marks it reviewed, not proven.

OBSERVEDYou saw or measured it. "RPM froze after screen-off on build 1.4.0."
INFERREDA reasonable guess, labelled as one. "The OS may close the socket."
SUPPORTED BY TESTBacked by a run. "1.4.1 keeps telemetry alive through 60 s off."
UNKNOWNNot established yet, and nobody pretends otherwise.

Pick up where you left off RESUME

Resume capsules

One screen generated from your records: the current failure, the last run, what's known, what's still unknown and the next action. Saved capsules never get rewritten. When records change afterwards, the capsule is marked STALE so you know to regenerate it.

Search and timeline

Search every project for "broken pipe" or a build number and jump straight to the run, plan or evidence. Each investigation keeps a timeline of everything that happened, in order.

Fix requests HANDOFF

When you need help, BLACKBOX writes the bug report you wish people sent you. Pick which evidence goes in, review anything that looks sensitive, edit the Markdown, then copy, save or share it. Nothing is sent automatically.

## OBD values freeze after screen-off

### Known gaps

On-device AI OPTIONAL · OFF BY DEFAULT

Runs on the phone

  • Import a LiteRT-LM model file (for example Gemma 3 1B). It runs on the CPU. No key, no account, no bill.
  • Ask it to suggest next tests, summarize what's known, or find gaps and contradictions.
  • You tick exactly which records it reads.

Kept on a short leash

  • Projects marked LOCAL ONLY are refused, even by the on-device model.
  • Every answer must cite the records it used. Answers citing records it wasn't given are thrown out.
  • Anything you keep is saved as an INFERRED claim, authored by "ai". It's still a guess until you test it.

Built for the Fold ADAPTIVE

Folded

One column on the cover screen, made for capturing quickly with one hand.

Unfolded

Two panes: your investigations on one side, the workbench on the other.

Half open

On the run screen, tabletop posture splits controls from the record, so the phone props itself up on the bench.

Folding, unfolding or rotating mid-run never loses your place, duplicates a run or restarts a recording. Normal phones get the same app in one or two columns depending on width.

Privacy LOCAL ONLY

  • No internet permission at all. The app cannot send anything anywhere.
  • No account, analytics, ads or telemetry.
  • Android cloud backup is turned off for BLACKBOX data.
  • Back up with Export project archive: a .zip of every record and attachment, with checksums.
  • Importing an archive always creates a new project. It can never overwrite existing work.
  • Uninstalling deletes everything that hasn't been exported.

Install SIDELOAD

  1. On the phone, open the latest release and download the APK under Assets.
  2. Open the file. When Android asks, allow your browser or file manager to install unknown apps.
  3. Tap Install, then open BLACKBOX and load the labeled sample project to look around.

Requirements

Android 10 or newer. Designed for the Galaxy Z Fold, and works on any phone. The on-device AI is optional and needs a model file of roughly 0.5–4 GB plus patience.
